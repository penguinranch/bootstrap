# 🧭 Adopting These Standards in an Existing Project

> For AI agents and developers told to _"use the best practices and standards set by this repo"_ who already have a project underway and don't want to run the installer.

Starting a brand-new project? Stop here and follow the [README](README.md) instead. The installer gives you everything below in one step.

## How to Use This Guide

1. **Do not run `install.sh`.** It's built for empty directories and refuses to overwrite an existing project.
2. **The [`/templates`](templates/) directory is the canonical source.** Every file referenced below lives there, exactly as it would land in a new project. Root-level files (like `install.sh` and the root `Makefile`) manage this repository itself, so ignore them.
3. **Fetch files directly** when working remotely:

   ```text
   https://raw.githubusercontent.com/penguinranch/bootstrap/main/templates/<path>
   ```

4. **Adopt in tier order.** Tier 1 fits any project with zero restructuring. Stop at whatever tier matches the project's appetite.
5. **Replace placeholders** as you copy: `{{PROJECT_NAME}}` (devcontainer.json and the Makefile's `APP_NAME`), `[SECURITY_EMAIL]` (SECURITY.md and CODE_OF_CONDUCT.md), `[Year]` / `[Full Name]` ([LICENSE](templates/LICENSE)), and the `@core-maintainers` / `@tech-leads` / `@devops` team slugs (CODEOWNERS).
6. **Record the source commit.** Resolve it with `git ls-remote https://github.com/penguinranch/bootstrap main` before fetching (or fetch from `.../bootstrap/<sha>/templates/<path>` instead of `main`, so the files match the commit). Put it in the adoption PR body, or in a `.bootstrap-version` file with `commit=<sha>` and `installed=<YYYY-MM-DD>` lines. That's the format `make bootstrap-sync` reads, and a future standards sync can start from that commit instead of re-auditing everything.

## Tier 1: Universal Guardrails (adopt everywhere)

Drop-in files that prevent whole categories of mistakes without changing how the project is built or run. One exception: the hooks take over `core.hooksPath`, so check for an existing hook manager first (see below).

| Practice                    | Source                                                                                              | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | --------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Consistent editor behavior  | [`templates/.editorconfig`](templates/.editorconfig)                                                | Enforces indentation, charset, final newlines in every IDE.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| LF line endings for scripts | [`templates/.gitattributes`](templates/.gitattributes)                                              | Stops Windows line endings (CRLF) from breaking bash scripts checked out on Windows. Scripts, hooks and config stay Unix line endings (LF).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Secrets never committed     | [`templates/.env.example`](templates/.env.example) + [`templates/.gitignore`](templates/.gitignore) | Real values live in `.env` (gitignored). `.env.example` documents every variable. Add new variables to `.env.example` first.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Conventional Commits        | [`templates/.githooks/commit-msg`](templates/.githooks/commit-msg)                                  | Enforces `<type>[optional scope]: <description>` on every commit. A `!` after the type/scope marks a breaking change (the hook accepts it).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Pre-commit secrets + lint   | [`templates/.githooks/pre-commit`](templates/.githooks/pre-commit)                                  | Scans staged changes for secrets (gitleaks), then runs `make lint`. The secret scan needs gitleaks, which ships in the devcontainer image (Tier 3). Outside it the scan is skipped with a warning. The lint step is skipped (with a warning) if `make lint` isn't available yet. The no-silent-pass guarantee (lint fails when shellcheck is missing, instead of passing having checked nothing) holds only with the template's `lint` target (Tier 2).                                                                                                                                                                                       |
| Consistent formatting       | [`templates/.prettierrc`](templates/.prettierrc)                                                    | Keep whatever formatter the project already uses. The practice is _a_ shared formatter config in the repo, not Prettier per se.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Shared spelling dictionary  | [`templates/cspell.json`](templates/cspell.json)                                                    | Approved words (product names, tools, identifiers) live in the repo, so a term gets approved once for everyone. Seeded with the words the payload's own files need, which is verified by spell-checking a pristine payload. Add project terms as they come up. `useGitignore` is on, so build output and dependency trees are skipped rather than producing thousands of unknown words the moment a project has a `_build/` or a `target/`. Once `cspell` is a local npm dev dependency (`node_modules/.bin/cspell`), the payload's `lint` target runs it, which makes it a pre-commit gate. CI runs `make lint`, so it's enforced there too. |
| Shared shell lint standard  | [`templates/.shellcheckrc`](templates/.shellcheckrc)                                                | Turns on optional ShellCheck rules the payload already passes, so the editor extension and `make lint` agree and new scripts can't regress below the bar. Run `shellcheck` on the project's scripts after copying and drop any `enable=` line they don't pass yet, so the file ratchets instead of creating a backlog.                                                                                                                                                                                                                                                                                                                        |
| Shared markdown standard    | [`templates/.markdownlint-cli2.jsonc`](templates/.markdownlint-cli2.jsonc)                          | Line length is left to the formatter and the rules that fight GitHub alerts and PR templates are off, so what remains is real structural breakage. Docs are most of what an AI agent reads, so it pays to keep their structure sound. The payload's `lint` target runs `markdownlint-cli2` once it's a local npm dev dependency. CI runs `make lint`, so it's enforced there too.                                                                                                                                                                                                                                                             |

**Activate the hooks** after copying `.githooks/`. First check `git config core.hooksPath` and `ls .git/hooks`. If a hook manager is already in place (husky, lefthook, pre-commit), port the gitleaks scan and the commit-msg check into it instead of switching `core.hooksPath`, which would silently turn the existing hooks off. Otherwise:

```bash
git config core.hooksPath .githooks && chmod +x .githooks/*
```

## Principles to Enforce Regardless of Files Copied

Even where none of the files above fit, hold the project to the underlying rules:

- **Host isolation:** never install project tooling on the host when a container is the declared environment. Wait until you're inside it.
- **Secrets in `.env` only**, documented in `.env.example`, never committed. Parse `.env` against an allowlist of known keys. Never blindly `source` it.
- **Decision-first workflow:** significant changes get a one-line entry in the `docs/ARCHITECTURE.md` Decision Log before code, and a CHANGELOG entry after.
- **Evidence over claims:** "done" means verified against actual command output, quoted in the report. Anything unverified is reported as unverified, never rounded up to working.
- **Idempotency:** setup and lifecycle scripts must be safe to re-run. Interactive prompts never belong in automated lifecycle hooks.
- **Pragmatism:** build for today's requirements (you aren't gonna need it, keep it simple). No premature abstraction.
- **One task interface:** people and agents run `make test`, not stack-specific commands. Every new command (migrations, generators, seeds, one-offs) gets a Make target with a `## description`, even a one-line passthrough. `make help` is the only command anyone needs to remember.

## Adoption Checklist

Copy this into the PR that introduces the standards and check off what was adopted:

```markdown
- [ ] .editorconfig, .gitattributes, .prettierrc (or equivalent formatter config)
- [ ] cspell.json, .shellcheckrc, .markdownlint-cli2.jsonc
- [ ] .env / .env.example secret hygiene, .gitignore covers .env
- [ ] .githooks (commit-msg + pre-commit) activated via core.hooksPath, or ported into the existing hook manager
- [ ] Makefile with standard targets mapped to the real stack
- [ ] dependabot.yml covering all package ecosystems in use
- [ ] CI workflow (lint + test on every PR)
- [ ] Security scan workflow (Trivy)
- [ ] PR template, issue templates, CODEOWNERS (slugs updated)
- [ ] SECURITY.md and CODE_OF_CONDUCT.md (contact filled in), CONTRIBUTING.md, CHANGELOG.md
- [ ] AGENTS.md adapted to this project
- [ ] docs/ living documents (VISION.md, ARCHITECTURE.md, MEMORY.md), with the adoption itself recorded in the Decision Log
- [ ] ai-context script, context-for-ai.md in .gitignore
- [ ] MCP config (.mcp.json, .gemini/settings.json) pruned to the servers in use
- [ ] .mcp/package.json and its lockfile, setup-mcp.sh, the make ai-mcp target and the /.mcp dependabot entry, if the local MCP servers are kept
- [ ] make browsers run once, if the playwright MCP server is kept
- [ ] devcontainer plus its lifecycle scripts (optional, see Tier 3)
- [ ] setup-env.sh / doctor.sh / utils.sh (needs the devcontainer)
- [ ] Source commit recorded (PR body or .bootstrap-version), bootstrap-sync.sh if using the stamp
```
